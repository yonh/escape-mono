# 执行日志：M5 子集——持久化存档

- 日期：2026-10-05
- 分支：feat/m5-save
- 里程碑：M5 打磨 · 存档子集

## 目标

游戏此前零磁盘持久化：stash/装备/战绩全是静态变量，重启进程即丢——
塔科夫式循环的「仓库跨会话留存」幻想缺失，属完整度最大缺口。

## 交付

- `save_kit.gd`：serialize/save/load_save/has_save/wipe。
  - 持久化：stash、backpack、loadout 四槽、stash_pending、raid_pending、
    raids_completed/departed、raid_map_id → `user://save.json`（version=1）。
  - 坏档/版本不符 → 返回 false 不崩；`SAVE_PATH` 是 static var（测试重定向）。
  - `wipe()` 新周目：删档 + 清内存态。
- 保存点（4 处）：
  - hideout `_ready` 先 `load_save()` 再 `_seed_stash_first_run()`
    （首局无档才发新手物资，有档跳过）
  - `_depart()` 出发前落盘（整装+仓库快照）
  - hideout `NOTIFICATION_WM_CLOSE_REQUEST` 关窗落盘
  - raid `_do_extract` 结算后、`dead_timer` 归零回屋前各落盘一次
    （阵亡/MIA 语义：背包已清、仓库保留）
- 中途退 raid = 弃局不写盘（同 MIA 丢包语义）。
- `test_save.gd`：无档/写读回环/满仓 pending 留存/坏档容错/wipe 五段。

## 验证

- `--import` 无 SCRIPT ERROR；11/11 headless 测试全过。
- 检查点：serialize 前先 `GAME_STATE.ensure()`——ensure 尾部
  `drain_stash_pending()` 会把 pending 有空间即并入 stash（语义=物品不丢）；
  满仓 pending 无处可去才留存进档。

## friction

- `"…%s" % array` 的坑：右操作数是 Array 时 `%` 把它当参数列表展开，
  空数组报 "not all arguments converted"——包一层 `[x]`。
- 填仓测试踩堆叠：scrap_metal（stack 4）find_space 反复返回同一未满堆
  → 死循环风险；改用不可堆叠件（ak74 + gp_coin 补碎格）。
